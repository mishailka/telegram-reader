# Telegram Reader для Codex · 0.2.0

Личный плагин для Windows: чтение Telegram, поиск по переписке, просмотр контекста, скачивание вложений и отправка текстовых сообщений. Каждый пользователь подключает собственный аккаунт на своём компьютере.

## Быстрый старт

1. Установите Codex для Windows. Нужен Python 3.11–3.14: установщик сначала ищет Python из окружения Codex, затем системный Python. Если подходящего Python нет, установите его с https://www.python.org/downloads/windows/.
2. Скачайте [исходники с GitHub](https://github.com/mishailka/telegram-reader/archive/refs/heads/main.zip) и распакуйте архив в обычную папку. Либо выполните `git clone https://github.com/mishailka/telegram-reader.git`. Запустите **Install.cmd**. Установщик скачает зависимости из PyPI, создаст отдельное окружение и установит личный плагин Codex. Права администратора не нужны. Для регистрации используются системные помощники `plugin-creator` из установленного Codex; если их нет, обновите Codex и откройте его один раз.
3. В открывшемся локальном окне введите `api_id` и `api_hash` своего приложения из https://my.telegram.org/apps и номер телефона Telegram.
4. Введите код входа из Telegram и, если включена двухэтапная проверка, пароль. Эти данные вводятся только в локальное окно, не в чат Codex.
5. Выберите отдельные чаты или все чаты и нажмите «Сохранить подключение».
6. Откройте **новую задачу Codex**, выберите плагин **Telegram Reader** и попросите: «Покажи доступные чаты».

Если плагин ещё не отображается, перезапустите Codex. Для повторного входа или изменения доступа используйте **Connect.cmd**. Не обновляйте страницу настройки: одноразовый ключ окна удаляется из адресной строки после загрузки. При необходимости запустите Connect.cmd заново. Окно действует 20 минут.

Если Windows блокирует скачанный ZIP, откройте его свойства → «Разблокировать» перед распаковкой. Глобально менять политику PowerShell не требуется: Install.cmd задаёт её только для процесса установки.

## Возможности

| Инструмент | Что делает |
|---|---|
| `connection_status` | Проверяет аккаунт и список разрешённых чатов |
| `list_chats` | Показывает чаты, идентификаторы, непрочитанные и архив |
| `read_history` | Читает историю с датами и пагинацией, не отмечая прочитанной |
| `search_messages` | Ищет в выбранном чате по тексту, отправителю, датам и типу вложения |
| `message_context` | Показывает сообщение и соседние сообщения в хронологическом порядке |
| `download_attachment` | Скачивает выбранное вложение в локальный файл |
| `prepare_message` | Готовит локальный черновик с точным получателем и текстом |
| `send_message` | Отправляет подготовленный черновик один раз |
| `message_delivery_status` | Показывает сохранённый результат отправки |

Codex отправляет сообщения только по прямому поручению пользователя. Просьба подготовить ответ не означает разрешение отправить его. Повторного подтверждения ясного поручения не требуется. Удаления, редактирования, пересылки, отправки файлов и отметки «прочитано» пока нет. У плагина нет инструмента произвольного вызова Telegram API.

Примеры:

- «Прочитай чат с Иваном за последние три дня и собери договорённости с источниками».
- «Найди документы, которые присылали в группе проекта».
- «Покажи контекст сообщения 12345 в выбранном чате».
- «Подготовь ответ клиенту, учитывая нашу переписку».
- «Напиши Ивану: Буду через 15 минут».
- «Ответь на сообщение 12345 в этом чате: Договорились».

## Отправка и защита от дублей

`prepare_message` проверяет числовой ID чата, разрешённую область доступа и сообщение, на которое нужно ответить. Возвращает точный текст и получателя; ничего не отправляет. Черновик действует 30 минут. `send_message` принимает только идентификатор этого черновика, поэтому текст и адресат между подготовкой и отправкой не меняются.

Текст отправляется буквально, без интерпретации Markdown/HTML; предел — 4096 единиц UTF-16. Поддерживаются ответ на сообщение, тихая отправка и предпросмотр ссылки (по умолчанию выключен). Платные сообщения за Telegram Stars не разрешаются.

Атомарная запись в локальном журнале защищает один черновик от повторной отправки, в том числе из нескольких процессов Codex. Telegram также получает постоянный `random_id`. Успешный результат содержит ID сообщения и означает принятие Telegram, а не прочтение адресатом. При тайм-ауте, прерывании или неизвестном ответе плагин сохраняет неопределённый статус и блокирует повтор: сначала нужно проверить историю. После явного FloodWait/SlowModeWait можно повторить тот же черновик по истечении указанного времени. Создание нового черновика с тем же текстом считается новой отправкой — автоматически так обходить неопределённый результат нельзя.

Повторный вход после обновления с 0.1.0 не нужен. Ранее выбранный список чатов используется и для отправки; конкретные сообщения отправляются только по поручению пользователя.

## Что пока ограничено

- Поддерживается Windows. Секретные чаты не поддерживаются.
- Поиск — обычный поиск Telegram по одному чату за вызов. Для поиска по нескольким чатам Codex делает несколько запросов. Семантического индекса нет.
- Есть фильтр основной список / архив. Пользовательские папки Telegram и полные ветки обсуждений пока не реализованы.
- Один аккаунт на пользователя Windows. Для замены аккаунта сначала отключите текущий через окно подключения.
- Диалоги просматриваются максимум до 2000 за вызов; инструмент сообщает о достижении границы. Порядок списка может меняться с новыми сообщениями.
- История выдаётся страницами по 1–100 сообщений. Даты ISO без часового пояса интерпретируются как UTC. `since` включительно, `until` исключительно.
- Скачивание: 20 МиБ по умолчанию, максимум 50 МиБ. Защищённые и исчезающие вложения не скачиваются. Автоматической расшифровки голосовых нет.
- Нет фонового наблюдения, ежедневных сводок по расписанию и автоответов.
- Подключение напрямую к Telegram. Отдельная настройка прокси в версии 0.2 отсутствует.

## Где хранятся данные

| Данные | Расположение |
|---|---|
| Изолированное окружение Python | `%LOCALAPPDATA%\TelegramReader\runtime` |
| Ключи приложения, сессия, разрешённые чаты | `%LOCALAPPDATA%\TelegramReader\account\account.dpapi` |
| Зашифрованные исходящие черновики и журнал результатов | `%LOCALAPPDATA%\TelegramReader\account\outbox.sqlite3` |
| Скачанные вложения | `%LOCALAPPDATA%\TelegramReader\account\downloads` |
| Установленный исходный плагин | `%USERPROFILE%\plugins\telegram-reader` |
| Личный каталог плагинов Codex | `%USERPROFILE%\.agents\plugins\marketplace.json` |

В сборке Codex из Microsoft Store Windows может перенаправлять LocalAppData в каталог приложения. Установщик сохраняет фактические абсолютные пути в установленном `.mcp.json` и `Connect-local.ps1`, чтобы окно входа и MCP использовали одну сессию независимо от способа запуска. В переносимый ZIP эти локальные настройки не включены.

Сессия, ключи и содержимое исходящих черновиков зашифрованы Windows DPAPI для текущего пользователя Windows. Код входа и пароль двухэтапной проверки не записываются в файл. Скачанные вложения — обычные локальные файлы без дополнительного шифрования. Полная входящая история на диск не сохраняется. Исходящие черновики и результаты отправки остаются в локальном журнале; текст и результат зашифрованы DPAPI. Идентификатор аккаунта, идентификатор черновика, время создания и состояние записи хранятся в SQLite открыто.

DPAPI защищает файл при переносе на другую учётную запись Windows; программы, запущенные под вашей учётной записью, потенциально могут получить доступ к данным. Telegram выдаёт полноценную пользовательскую сессию: ограничения операций и разрешённых чатов обеспечивает код этого плагина, а не отдельный режим прав Telegram.

Сообщения, возвращённые инструментом, передаются в контекст Codex для анализа. Локальный сервер не означает полностью локальную обработку моделью. Не передавайте другим папку `account`, её содержимое или весь каталог `TelegramReader` из LocalAppData.

При завершении настройки незавершённая авторизованная сессия по возможности отзывается. При аварийном завершении процесса лишнюю сессию можно отозвать в Telegram → Настройки → Устройства. Это также основной способ немедленно отключить доступ при недоступности компьютера.

## Как передать другим

Отправьте ссылку на [этот репозиторий](https://github.com/mishailka/telegram-reader). Получатель скачивает исходники через **Code → Download ZIP** или клонирует репозиторий, запускает **Install.cmd** и подключает собственный Telegram с собственными `api_id`/`api_hash`. Учётные данные автора не входят в исходники.

Это локальный плагин для Windows с отдельным установщиком. Добавление ссылки в каталог Codex само по себе не устанавливает окружение Python. Для обновления скачайте свежую версию или выполните `git pull`, затем снова запустите **Install.cmd**; существующее подключение сохраняется.

Не архивируйте весь установленный каталог самостоятельно: используйте подготовленный архив. При ручной передаче исходников оставляйте `.mcp.json` из исходного пакета; установщик сам подставляет локальные пути получателя.

## Проверка и разработка

Архитектура: Python → Telethon → Telegram MTProto; MCP stdio → Codex. Окно входа — временный HTTP-сервер, привязанный только к `127.0.0.1`. Изменения требуют одноразовый токен, ожидаемый Origin и Host. На stdout MCP идут только сообщения протокола.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install -e . pytest pytest-asyncio
.\.venv\Scripts\python.exe -m pytest tests -q
```

Тесты используют фиктивный Telegram-клиент, проверяют границы доступа, пагинацию, даты, загрузку, очистку неполных файлов, DPAPI, отправку без дублей, сбои/отмену/лимиты, окно входа и реальный запуск MCP через stdio. Они не заменяют проверку на настоящем подключённом аккаунте.

Официальные и первичные источники: [создание приложения Telegram](https://core.telegram.org/api/obtaining_api_id), [Telethon](https://docs.telethon.dev/en/stable/), [MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Протокол отправки: [messages.sendMessage](https://core.telegram.org/method/messages.sendMessage).
